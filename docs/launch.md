# GitHub launch plan

## Private review

Choose the GitHub owner, review visibility and confirm the license for original contributions. Stage the repository privately for editorial review. Confirm the December calendar before advertising the briefing and select a maintainer for filing and correction review. Use the [source report audit](source-report-audit.md) during sign-off. Keep private source files and working notes outside the repository.

## First public release

- **Repository slug** `jensen-huang-research`
- **Description** Independent research on Jensen Huang, NVIDIA, and AI infrastructure, with an evidence ledger, governance timeline and reproducible financial data.
- **GitHub topics** `jensen-huang`, `nvidia`, `ai-infrastructure`, `corporate-governance`, `open-research`, `semiconductors`, `export-controls`, `sec-edgar`, `reproducible-research`
- **Launch asset** A date-stamped social card showing the effective and public disclosure dates and a short URL to the evidence ledger. Use the project title and original typography.
- **Release** Publish tag `v0.1.0` with the dated briefing, data dictionary, correction policy and reproducibility commands. Populate citation metadata with the canonical repository URL once assigned. Pin the project from the maintainer profile if appropriate.

GitHub's [repository topics](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics) and [release tools](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository) support discovery and stable version references.

## First month

| When | Action | What to measure |
|---|---|---|
| Launch week | Share a short methodology post with the effective-date example in a semiconductor or open-research community that welcomes project posts. Link the reproducible table and invite one narrowly scoped correction. | Unique visitors, clones and useful source submissions |
| After the congressional calendar clears | Publish a dated follow-up linked to the official record and state which events changed, happened or remain pending. | Repeat readers and citations to specific claim IDs |
| Weeks 2–4 | Offer starter issues for one historical date, one archive locator and one peer-financial comparison. Give each issue a definition of done. | Time to first review and number of accepted evidence contributions |
| End of month | Review which pages are used, which sources need upkeep and which research issue attracted substantive contributions. Choose the next release accordingly. | Correction turnaround, referrals and validated contributions |

Record GitHub's short-window traffic totals weekly to compare launch channels. Treat stars as an interest signal and use reproducible reuse, citations and corrections to assess research value. [GitHub traffic documentation](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository)

## Observatory release

Release the observatory after the review checks pass. Include the project ZIP and two English graphics exported by the browser. Start the release note with one answer readers can source in a minute. Use the timeline’s resignation and reinstatement record or the November policy publication and effective-date pair.

For the first week, choose a narrowly scoped task for each audience:

- **Researchers:** trace a dated prior-quarter revenue input to the issuer’s exact page and verify the comparison period.
- **Journalists:** check a congressional calendar entry and link official testimony or a schedule change.
- **Developers:** reproduce the four published benchmark rows from the pinned MLCommons CSV and report any mismatch.

Use the [observatory instructions](observatory.md) to verify the guest-facing page and the download path. Add the published Pages URL to the repository About section after a successful deployment. The image export includes a versioned research cutoff or date so readers can return to the source repository.
